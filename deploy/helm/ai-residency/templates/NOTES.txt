AI Residency Portfolio deployed to namespace "{{ .Release.Namespace }}".

Images are pulled from Docker Hub (roshbeed/ai-residency-weekN-serve / -train), published by each
week repo's own `make docker-push-serve` / `docker-push-train`. If you've republished any
image, pull it and roll the pods:

  docker pull roshbeed/ai-residency-word-embeddings-serve:latest   # (or whichever changed)
  kubectl rollout restart deployment -n {{ .Release.Namespace }}
  # or just: make helm-upgrade (re-applies the chart and restarts deployments for you)

Frontend (LoadBalancer -- Docker Desktop binds this to localhost automatically):

  kubectl get svc frontend -n {{ .Release.Namespace }}
  open http://localhost:{{ .Values.frontend.servicePort }}

Backends are ClusterIP-only (mirrors production shape: only the frontend talks to
them directly). To reach one from your Mac for debugging, port-forward it (remote port
below is each backend's real containerPort, not a hardcoded guess -- if you've
overridden a backend's containerPort in values.yaml, these reflect that override):
{{- range $name := (keys .Values.backends | sortAlpha) }}
{{- $svc := index $.Values.backends $name }}
  kubectl port-forward -n {{ $.Release.Namespace }} svc/{{ $name }} 800{{ trimPrefix "week" $name }}:{{ $svc.containerPort }}
{{- end }}

One-time step for vector-search-retrieval (same as the docker-compose version -- this cluster's own
redis starts empty):

  kubectl exec -n {{ .Release.Namespace }} deploy/vector-search-retrieval -- uv run python -m retrieval.save_doc_embeddings_to_redis

Check status:

  kubectl get pods -n {{ .Release.Namespace }}

Memory note: this node's allocatable memory (`kubectl describe node`) is likely well under what all
8 pods' memoryRequest values add up to, on purpose (see values.yaml's comment above `backends:`) --
some pods may sit Pending rather than all 8 crash-looping over scarce memory. Free room for a
Pending one with:

  kubectl scale deploy/<name> -n {{ .Release.Namespace }} --replicas=0
